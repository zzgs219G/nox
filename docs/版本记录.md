# 版本记录

> **本文件是 nox 的版本真相表。** 与 `git tag` 两条线都要维护：
> - `git tag` = 可复现的代码快照
> - 本表 = 人能读的版本说明
>
> ⚠️ **换版时必须同时做三件事**：打 tag、更新本表、更新消费方的
> `artifact-pipeline/tools/工具包版本.md`。曾因漏更新消费方那行，
> 版本表落后 25 个版本（11-13 实测发现）。
>
> 核对方法：
> ```bash
> git describe --tags           # 仓库当前 tag
> unzip -p ../artifact-pipeline/tools/nox.zip nox/VERSION   # 消费方实际用的
> ```
> 两者必须一致。

### v0.9.40-md-report-obf（2026-11-14）当前版

**只有自检报告的可读性改动，防护行为零变化。**

① 段表表头与数据行对齐（用户反馈「文本歪歪扭扭」）
   · 表头原是三行手写字面量，与数据行的 `%9llu / %-4s / %6.3f` 格式串
     毫无关系 → 逐列错位。实测表头 `[0,10,18,25,31,53]`、
     数据行 `[0,13,21,27,34,52]`。
   · 改为按实测列位写死的字面量，注释写明「改 rp_seg 格式串必须重算」。
   · 试过用 rp_pad 逐列补绝对列位，失败：rp_pad 语义是「补到总宽至少
     N 显示列」，不是「补到列 N」，会算出 20+ 空格。

② 判定前缀宽度统一为 2 字符
   · `! 样本不足`（1空格）与 `!  高熵未解密`（2空格）宽度不一
   · fallback 的 `明文`/`密文` 无前缀 → 补 3 空格与 `OK `/`XX ` 等宽

③ 体积归因（上一提交 8cf109e 已含）
   · 按 nox设施 / VMP载荷 / 业务载荷 / 基础代码 四组汇总 + 组内明细
   · 整组不存在也打 0 B（区分「没开 VMP」与「统计漏了」）

**断言**：V12g（四组齐全）/ V12h（有合计行）/ V12i（表头与数据行列位一致）。
V12i 不比较大小和熵 —— 它们右对齐，起始列随数字位数变化，比起点会误报。
nox test.sh 44 通过 0 失败。

## 版本历史

### v0.9.37-plain（2026-11-13）当前版

**段架构重定 + 体积优先**

| 改动 | 说明 |
|---|---|
| 两套 VMP 段名分开 | 第一套 `.ncq`/`.ncs`，第二套 `.ncv`/`.ncw`。同名会混淆 → SIGSEGV（K-06） |
| `.nct`/`.ncv` 不加密 | 实测加密后 APK 压后 +150KB，强度增益接近零。保留 `.ncx`/`.ncxr`/`.ncxh` |
| 自检报告 | 解锁后打体检日志到 `files/ncguard_log.txt`，开关 `/storage/emulated/0/xixin_debug` |
| 段列表用数组 | 修"同名段被加密两次 = RC4 两次 = 明文"（K-07） |
| 三处 `.c` 清单改动态扫描 | 修"漏一个文件 → dlopen 报 undefined symbol"（K-09） |
| 文档大修 | `so防护架构.md`（原混淆计划）/ `踩坑记录.md` K-01~K-11 / `变更历史.md` |

**依赖**：amice `v0.1.6-nox16`、artifact-pipeline 的 `protect.sh` 需同步改段名。

### v0.9.29-nct-fix（2026-11-12）

**`NCGL_INSN` 11 → 10** —— 真机 SIGILL 的真因不是 Amice，而是 label 长度写错。

当时状态：`.nct` 加密方案失败（首版 SIGILL），回滚到 `.nct` 不参与解密。

### v0.9.26 ~ v0.9.28（2026-11-12）

`.nct` 段进锁箱的三次尝试，全部失败：

| 版本 | 改动 | 结果 |
|---|---|---|
| v0.9.26-nct-obf | `.nct` 段进锁箱 | ❌ SIGILL |
| v0.9.27-nct-obf | 段序改动态 + 修正段名抽取正则（`NC_SEC_VMP2` 带数字） | ❌ 仍崩 |
| v0.9.28-nct-plain | `.nct` 不参与解密 | 回滚 |

**当时的判断（后来证伪）**：以为是"段名导致崩溃"。
**真因**（11-13 查明）：`.ncr` 里有 83 个 `R_AARCH64_RELATIVE` 重定位，
整段加密后解锁写回会覆盖链接器填的指针 → 垃圾指针 → SIGILL。
**与段名无关**，与"是否含指针"有关。

### v0.9.12 ~ v0.9.14（2026-11-10 ~ 11-11）

VMP 恢复 + `runtime.entry` call → inline。

- v0.9.12：`entry=inline` 消除 `bl <dispatcher>` 明路标（303 次 bl 集中指向同一地址 → 一条 grep 定位全部 handler）
- v0.9.14：拆 `ncg_derive_kso_bound`，降 `ncg_head_unlock` 的 alloca

### v0.9.11-obf（2026-11-11）

**关闭解密链 VMP**（`v0.9.11-novmp`）。理由见 `so防护架构.md` §14：
零信息逆向用 unicorn 17 分钟拿到 `boot_key`，14 个 VMP 函数一个没读懂但输出全拿到。

**该决定后来被推翻**（11-12 恢复），但核心结论仍成立：
"要结果 → VMP 无效；要逻辑 → VMP 有效"。

### v0.9.0 ~ v0.9.10（2026-11-06 ~ 11-09）

VMP 覆盖率从 1 个函数做到 14 个（`ncg_boot_key` / `ncg_xor_key` /
`ncguard_stub_recover` / 包名路径等）。升档到 `scope=func` + `handler_clone=func`
（函数级隔离，逆通一个只能读一个）。

## 版本号命名约定

```
v0.9.<序号>-<标签>
```

**标签含义**（尽量用能说明改动的词）：

| 标签 | 含义 |
|---|---|
| `-plain` | 段不加密（明文优先，体积小） |
| `-obf` | 含 Amice 混淆（MBA + flatten） |
| `-vmp` | 含 VMP 虚拟化 |
| `-nct` / `-insn` / `-bc` / `-seg` | 该轮实验的段相关改动 |
| `-log` | 日志/报告相关 |

**⚠️ 标签不得暴露防护意图**（流程文档的通用纪律）。但版本标签留在这里是为
人类维护者服务的，不出现在产物里（产物只有 `VERSION` 文件一行版本号）。
